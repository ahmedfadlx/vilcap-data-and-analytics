Data at Village Capital

Where our program and investment data is created, where it gets lost today, and what changes when one function owns the analytical layer.

Today

Data sits in Abaca, VilData, Airtable, Upmetrics and dozens of Google Sheets and Forms. No one owns the analytical layer, so records go missing and teams rebuild the same work.

What it costs us

Only 3 of 26 headline metrics appear in all five impact reports since 2021. Survival rates, which leadership asks for, appear in one. Funder reports are rebuilt each time.

What we propose

A data and analytics function that owns the analytical layer. Teams keep the tools they know. The function puts the agreed metrics to work, brings our history into one place, and delivers analysis, dashboards and reporting.

Where each stage stands today

Why now

Building on the learning architecture

The Data Learning Architecture work (board update, 9 September 2026) agreed what VilCap measures and what a new system should do. It also named the gap a data function fills.

What the working group found

Key lessons from the board update, and how this proposal responds

Request channel

One channel for data requests

Program managers and the investment team post requests in one Slack channel. Each request gets an ID, a tier and a delivery date, and the log shows demand over time.

  1. Post the requestFill in the short form in #data-requests.
  2. TriageWithin one working day: an ID, a tier and any questions.
  3. ScopeFor standard and project requests, agree output, source and date.
  4. Build and checkWork on a copy of the data, checked before it goes out.
  5. Deliver and closeShared in the thread and marked done in the log.

Roadmap

How we get there

The work starts in January 2027, right after step 3 of the learning architecture (tech stack, August to December 2026), so it builds on the agreed metrics and the new system.

Jan to Mar 2027

Foundations

  • Launch #data-requests and the request log
  • Company IDs and a question bank built from the agreed metrics
  • Standard templates: application, tracker, feedback form, survey base
  • Inventory of every past data source, 2009 to 2026
  • First live read of the Direct Contribution level
Apr to Jun 2027

Connect

  • Syncs from Abaca and Airtable into one record per company
  • Past program and investment data compiled and cleaned into the archive
  • Scheduled PitchBook pull for follow-on capital and operating status
  • Quarterly portfolio form, with the investment team
Jul to Dec 2027

Learn

  • Business Health level live: follow-on capital, survival, jobs
  • History view: cohorts and outcomes since 2009
  • Pre/post outcomes across programs
  • Benchmarks: cost per beneficiary and conversion
2028 onward

Share

  • Impact report built on the full history, with the same metrics each year
  • Funder reporting from the same dataset
  • Methods for the top two levels: people impacted, AUM influenced

If the new system is live by January 2027, the Connect phase builds on it instead of the Google tools. The standards, IDs, templates and archive work either way.

Decisions needed from leadership

A mandate for the analytical layer

Clear ownership of data standards, quality and analysis across programs and investments.

Agreement on standards

Programs use the question bank, templates and the request channel.

Access

Edit access to VilData, Abaca exports, Airtable, program folders and past archives.

A data contact in each team

One named person per program and one in the investment team.

A small tools budget

For automation, storage and dashboard hosting, where free tiers are not enough.

A seat in the working group

A standing place in the learning architecture group, so both stay aligned.
